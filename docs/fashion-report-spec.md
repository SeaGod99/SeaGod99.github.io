## 0. 改版要解決的三個問題

改版前使用者的原話是「每次更新都會用不一樣的方式顯示」，加上兩個具體缺陷。逐一對應：

| 問題 | 根因 | 解法 |
|---|---|---|
| **每週顯示方式都不一樣** | 答案的完整性寫在**人工散文**裡（`scoring.note100`／`easy80.note`／`easy80.desc`），不在資料結構裡。440 週給 4 件、441～443 給 3 件＋一段文字補充「其餘部位怎麼辦」；沒被推薦到的部位有時交代有時不交代 | 答案改為**涵蓋所有計分部位的配裝表**（§3），每週結構完全相同，散文欄位全部刪除 |
| **染色成本被當成 0** | 推薦標準只排「裝備的取得管道」，染劑當作免費且必然買得到 | 成本模型把染劑計入，並把「買不到」獨立成**門檻**維度（§2） |
| **完整清單只能複製名稱** | 每列只有名稱＋可交易＋一句取得方式 | 加上等級／職業／可否染色／性別種族限制／販賣者與地圖／市場板連結／英文名，並可篩選排序（§4） |

## 1. 計分模型

```
分數 = 基礎分
     + Σ 提示部位穿對（防具 +8／飾品 +6）
     + Σ 六個左側部位染上指定精確色（+2；同色系 +1）
     上限 100
基礎分 = 68（本週提示全是防具）／70（本週有飾品提示）
```

- 吃染色分的六個部位固定是 **武器・頭・身・手・腿・腳**。
- 評分前**每個部位都要穿著裝備**。
- 每週最多評 4 次；參加得 10,000 MGP，80 分以上再得 50,000 MGP，各每週一次。

**這個公式不是憑印象寫的，而且每次跑週更都會被回頭驗算**：`build-fashion-report.mjs` 拿來源站自家的 easy80／easy100 組成代入公式，算出來低於該分數就中止不出檔（week 443 實測：easy80 = 68+8+2×2 = 80 ✅、easy100 = 68+8×3+2×4 = 100 ✅）。遇到罕見的 +9 提示之類的例外會立刻被抓到，而不是安靜地給錯答案。

> **同色系 +1 本站一律不推薦。** 來源站的 `plus1` 是它自己的色名分類（例如把珍珠白歸為 white），但遊戲染色面板的分組（`Stain.Shade`）把珍珠白放在「特殊」而非白色系，兩者對不上。在沒有可靠依據前，推薦只用精確色 +2，避免給出實際少 1 分的方案。

## 2. 推薦標準（重訂）

### 2.1 舊標準錯在哪

舊標準是一條取得管道的優先序：`NPC 可購／兌換 → 市場板 → 製作 → 副本／掉落 → 零式／絕版`。它只看「裝備」，且假設染色免費。

拿 week 443 實測：舊頁面寫「**省事 80 分・全程 116 金幣**」，但那套要染兩個部位，其中**萄乾棕染劑只有南薩納蘭的蜥蜴人族雜用商人賣，需要部族聲望**；滿分方案要染的**東洲藍染劑是刻木匠製作限定、且不可交易**——沒有刻木匠的玩家根本做不到，頁面卻隻字未提。標價便宜，門檻卻可能高到做不到。

### 2.2 新標準

一套方案的代價分三層，**依序**比較（前一層分不出勝負才看下一層）：

1. **門檻**（能不能做到）：部族聲望、製作職業、限時活動、隨機掉落、台服未實裝。每種門檻有嚴重度權重，總和越小越好。
2. **金幣總額**（要花多少）：裝備 ＋ 染劑。**染劑每染一個部位就算一支**。沒有 NPC 固定價的件（只能製作或上市場板）不計入金額，但會單獨列出並在頁面標明「總額沒把它算進去」——不能假裝免費。
3. **件數**（要跑幾趟）。

單一部位選哪一件也照同一套：先無門檻、再便宜、再低需求等級。

### 2.3 怎麼算出來的

不是人工挑件，是**列舉求解**：把「要湊哪幾件提示裝」×「要染哪幾格」的所有組合（最多 2¹⁰ = 1024 種）全部展開，篩掉達不到目標分數的，再用上面三層比較挑出最佳解。因此結果是可證明的最省，也每週穩定可重現。

同時輸出兩個目標：**拿滿 MGP（≥80）** 與 **滿分（100）**。若最省解帶門檻，另外解一次「只用無門檻的件與染劑」當替代方案並列；若該分數線根本沒有無門檻解，就明講「本週沒有」，不粉飾。

> week 443 的實際效果：80 分線由「116 金幣＋2 支染劑＋部族聲望」變成 **146 金幣・0 染劑・0 門檻**；100 分線由「12,916 金幣＋4 支染劑＋部族聲望＋刻木匠」變成 **472 金幣・0 染劑・0 門檻**（另有 1 件身體裝需製作或市場板購入，已單獨標示）。

### 2.4 染劑的隱性成本（本次新增的資料層）

`data/dyes.json` 收錄 114 支台服已實裝染劑，每支都有顏色色票、遊戲染色面板分組、可否上市場板、以及完整取得管道（金幣價／兌換貨幣／製作職業／販賣 NPC 繁中名與座標）與門檻。統計出來的現實是：

- **只有 20 支可以上市場板**，其餘 94 支買不到就得自己跑 NPC 或自己做
- **62 支有門檻**（部族聲望／製作職業／限時活動等），只有 52 支真正無門檻
- 蠻族雜用商人（蜥蜴人・魚人・鳥人・風精靈・地靈）合計壟斷了一批常用色

### 2.5 填充裝

「其餘部位穿任意裝備染成 X 色」這句話有兩個坑：**不是所有裝備都能染色**，而且新玩家不見得有可染的裝。所以 `data/fashion-fillers.json` 為五個防具部位各指定一件「全職業可穿・NPC 直購・無門檻・確定可染」的具體裝備（全套 550 金幣）。

這張表是實測出來的，不是挑好看的：頭部最便宜的三頂蛋殼帽（11～28 金幣）`DyeCount` 都是 0，照著買會發現根本染不上去——被剔除的候選都留在該檔的 `rejected` 欄位當證據。

武器不做通用填充：武器一定有職業限制，沒有一件所有職業都拿得到的可染武器。頁面直接說明「用你自己職業的武器，不可染就放棄那 2 分」。

## 3. 版型：每週長得一模一樣

### 3.1 配裝表

方案的答案**永遠**是一張表，每列一個計分部位，順序固定 `武器→頭→身→手→腿→腳→（有飾品提示時才追加）耳→頸→腕→戒指`：

| 欄 | 內容 |
|---|---|
| 部位 | 部位名 ＋ 本週該部位的提示（沒有就不顯示） |
| 該穿什麼 | 三選一：**提示裝**（圖示＋名稱＋取得方式＋價格＋門檻＋販賣地點）／**穿現有可染裝備**（附填充裝退路）／**穿什麼都行，不影響分數** |
| 要染什麼 | 色票＋色名＋價格或取得方式＋門檻＋購買地點；不用染就寫「不用染」 |
| 得分 | 該部位貢獻的分數，沒有就是 `—` |

關鍵是**沒被推薦到的部位也一定有一列**，明講「穿什麼都行，不影響分數」。過去這件事只在人工散文裡偶爾交代，才會讓人覺得每週講法都不一樣。

### 3.2 資訊順序

`代價 → 門檻警示 → 配裝表 → 無門檻替代方案`。使用者先想知道「這要花我多少、我做不做得到」，再看要穿什麼。成本摘要固定四格：**裝備＋染劑金幣 / 件數 / 染劑支數 / 金錢以外的門檻**。

### 3.3 兩套方案並列

用分頁切換（「拿滿 MGP」與「滿分」），而不是同時攤開兩張長表。分頁標籤上直接寫該方案的金幣與門檻數，不用點進去就能比較。

## 4. 完整接受裝備清單

用途是「推薦那件穿不上或不喜歡時，換哪一件同樣計分」。所以每列除了名稱，還要回答「這件我拿不拿得到、穿不穿得上、能不能染」：

- **需求等級／裝等**、**可裝備職業**（全職業或職業數）
- **能不能染色**（`DyeCount`）——時尚品鑑常要染色，不可染的件等於少一條路
- **性別／種族限制**（`EquipRestriction`）——幻化的老陷阱
- **取得方式＋金幣價＋販賣 NPC 與地圖**（可點開地圖彈窗）、**門檻標籤**
- **可交易者連到站內市場查價**、**版本**、**複製英文名**（對照國際服攻略用）

預設依「好不好取得」排序（無門檻→有門檻→看運氣，同級比金幣）。可依部位、取得難度篩選，可依價格或需求等級排序，可搜尋中英文名。

## 5. 換週流程與狀態機

### 5.1 遊戲時序（台北時間，全年固定）

```
週二 16:00 ──────────── 週五 16:00 ─────────────── 下週二 16:00
  收榜 ＋ 新主題與提示揭曉        評分開放                 收榜（＝下一週的起點）
  ├────── 準備期（3 天）──────┤├────── 評分期（4 天）──────┤
  MGP 獎勵與 4 次挑戰次數同時重置
```

官方時刻是 PST 12:00 a.m.（固定 UTC-8、不套夏令時），換算台北時間全年固定 16:00，不會漂移。

**遊戲端沒有空窗期**——收榜與換主題是同一刻。

### 5.2 「過渡期」的真正定義

過渡期＝**本站資料落後於遊戲**的那段時間，跟遊戲時序無關。來源站 fashionreportxiv 在週二 16:00 後要幾十分鐘到幾小時才換週，而且它的 `lastOptions` **沒有新鮮度旗標**、週次會停在舊值。所以：

> **判斷資料是否過期，唯一可靠的方法是拿來源站的週次去比對本站用錨點自算的週次。**

因此狀態機把兩件事拆成獨立維度，絕不混為一談：

- **遊戲階段**：由時鐘算（準備期／評分期）
- **資料新鮮度**：資料檔週次 vs 當前週次，以及 `status`（`predicted`／`verified`）

### 5.3 六個狀態

| 狀態 | 條件 | 徽章 | 說明重點 | 主要行動 |
|---|---|---|---|---|
| 準備期・預測版 | 週次相符・`predicted` | 準備期 | 提示已揭曉但社群未實測，可先備裝 | 照表備裝 |
| 準備期・已驗證 | 週次相符・`verified` | 準備期 | 已對過實測，現在還不能評分 | 照表備裝 |
| 評分期・已驗證 | 週次相符・`verified` | 評分期 | 正常態，去假面薔薇評分，每週 4 次 | 去評分 |
| 評分期・僅預測版 | 週次相符・`predicted` | 評分期 | 尚未對過實測，建議先評一次確認 | 謹慎評分 |
| **本站未收錄・準備期** | 資料週次落後 | 未收錄 | 還不能評分，等更新或看外部來源 | 外部來源（次要） |
| **本站未收錄・評分期** | 資料週次落後 | 未收錄 | **最緊急**：評分已開放但本站沒答案 | 外部來源（主要按鈕） |

外加一個防呆狀態：資料週次超前（不該發生）。

### 5.4 資料落後時顯示什麼（過渡期的關鍵設計）

三條規則：

1. **標題顯示「現在這一週」的週次與主題，不是存檔那週。** 主題名可離線預查——`FashionCheckWeeklyTheme` 的 row ＝ 週次 + 9，`data/fashion-themes.json` 已預先算到 **week 525**（約 2028 年）。所以即使提示還沒收錄，頁面也能誠實地說「第 444 週・風信子冒險者，提示尚未收錄」，而不是一片空白或把上週答案擺在最上面。
2. **當前週次的階段徽章與倒數照常顯示。** 使用者最急的是「現在能不能去評分、還剩多久」。
3. **上週資料降級為存檔**，明確標示「那一週已經收榜，照著做不會得分」，並把外部來源升為主要行動。

### 5.5 腳本端的對應行為

`build-fashion-report.mjs` 在 API 週次 ≠ 本站週次時**主動拒跑並中止**，不覆蓋既有資料。這是刻意的：真空期硬寫下去會把正確的存檔蓋成錯的。前端已能自己處理這段時間，不需要人工介入。

## 7. 驗收

改完資料或前端必跑：

```bash
node scripts/validate-data.mjs
```

前端回歸在本機沒有 headless Chromium，改用 **DOM stub 跑 render()**（不需要 jsdom）：塞一份假的 `document`／`fetch`／`setInterval`，import 頁面的 module script，然後檢查產出的 HTML 有沒有各區塊、有沒有洩漏 `undefined`／`NaN`／`[object Object]`。狀態機要**七個狀態各跑一次**（六個正常狀態＋資料超前防呆），做法是把 `Date.now` 換成各狀態對應的時刻。

## 8. 已知限制

- **主題名與提示名是簡轉繁，非台服官方譯名**（台服沒有公開的對照表）。資料檔以 `nameSource`／`hintSource: "cn-hant"` 標記，頁面頁尾註明。裝備與染劑名則是台服官方名。
- **同色系 +1 未採用**（見 §1 的說明）。
- **染劑取得方式來自本站 7.2 離線資料**。國際服 7.5 已把單色染劑整併下架，Garland／XIVAPI／英文 wiki 都查不到，無法交叉驗證；等台服升到 7.5 時整個染劑層要重做。
- **蠻族商人的確切聲望階級沒有寫死**，只標「需部族聲望」——階級因染劑而異，寧可少講也不給錯數字。
- 市場板即時價尚未直接顯示在配裝表上（可交易件已可一鍵跳站內市場查價）。
