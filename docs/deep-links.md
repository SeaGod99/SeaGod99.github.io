# 深連結規約

站上有 30 個工具，其中 9 處會把狀態寫進網址。這份文件記錄**每個參數叫什麼、代表什麼**，
以及新頁面該怎麼取名，免得下一個功能又自創一套。

> 2026-09-25 建立。當時的實況是：搜尋大家都用 `q`（好），但分頁有的用 `?t=` 有的用 `#craft`，
> 而 `?c=` 在貨幣變現頁是「貨幣」、在雇員探險頁是「職業分類」——同一個字母兩種意思。

---

## 1. 通用參數（新頁面請優先沿用這些名字）

| 參數 | 意義 | 用在哪 |
|------|------|--------|
| `q` | 搜尋關鍵字 | 收藏追蹤引擎（13 頁）、季節活動商店、無人島 |
| `own` | 擁有狀態篩選（`all`／`owned`／`missing`） | 收藏追蹤引擎 |
| `sort` | 排序鍵 | 收藏追蹤引擎、無人島 |
| `f_<篩選 id>` | 某一組標籤篩選的選中值 | 收藏追蹤引擎 |
| `p` | 分頁頁碼（**1-based**，給人看的） | 收藏追蹤引擎（有 `pageSize` 的頁） |
| `id` | **連到特定一筆**（見下方 §2） | 收藏追蹤引擎 |
| `scope` | 市場查價範圍（`dc` 或伺服器 id） | 貨幣變現、雇員探險 |
| `tab` / `t` | 分頁 | 見下方 §3 的現況 |

**取名原則**：能沿用就沿用；真的要新參數就取**在該頁讀得懂**的短名，
並回來補進這張表。不要用單字母表示「某種東西的 id」——`c` 已經被兩種意思用掉了。

---

## 2. `?id=` ——「連到特定一筆」（收藏追蹤引擎，13 頁）

`/collections/mounts/?id=id%3A123` 會開啟坐騎頁、**自動翻到那一筆所在的分頁**、捲到它、閃兩秒。

- 值是**該頁 `keyOf` 的輸出**，不是物品 id。多數頁是 `'id:<id>'`，
  **寵物頁是純數字**（沿用舊存檔格式，§2.5 的相容性鐵則，不能改）。
  要產生連結的人請從該頁的資料算出 keyOf，或直接用本站的全站搜尋（它已經處理好）。
- 它是**一次性的導覽意圖**，不是頁面狀態：捲到之後就從網址移除。
  留著的話使用者每次改篩選都會被拉回那一筆。
- 對不到任何一筆（被篩掉、或根本不存在）就**安靜放棄**，不報錯也不清篩選。
- 與 `q`／`own`／`sort`／`f_*`／`p` 可以並存；`?id=` 只負責捲，不會動篩選。

實作在 `assets/js/collection-tracker.js` 的 `focusCard()`。

### 2.2 `#craft=` ——「帶一份材料清單過去」

`/tools/market/#craft=5057:3,5056:1` 會開市場頁的製作分頁，並把那兩件材料照數量加進清單。

- 值是 `<物品 id>:<數量>` 用逗號串起來；數量省略視為 1。
- 逐件走市場頁既有的 `addToCraft()`——**上限（`MAX_CRAFT_ITEMS`）與同物品合併的規則只有那一份**，
  產生連結的一方不要自己先去重或截斷。
- 查不到的 id（台服未開放或打錯）**安靜略過**，其餘照加，並提示略過了幾件。
- 也收 `?craft=` 查詢字串別名（同 §3 市場頁那列的說明）。

目前的產生方：製作模擬器 HQ 材料區的「💰 帶這些材料去市場頁算成本」。
數量用**總需求量**不是 HQ 欄位的輸入值——要查的是「做這一個總共要買幾個」。

### 2.1 系統解鎖索引的 `?id=`

`/tools/unlock-index/?id=sys:gold-saucer`／`?id=job:PLD` 用的是**同一套語意**
（捲到、閃兩秒、用完從網址移除、對不到就安靜放棄），但那頁不吃收藏引擎，
所以值是自己的命名空間：`sys:<系統 key>` 或 `job:<職業縮寫>`，
對應卡片上的 `data-key`。

產生連結的兩個地方**都不要自己拼字串**：

- 命令面板：`data/site-index.json` 的「系統解鎖」「職業行會」兩類已經帶好 key
  （`scripts/build-site-index.mjs` 產生）。
- 工具頁解鎖橫幅：`assets/js/unlock-banner.js` 從 `system-unlocks.json` 直接取 `key`。

兩邊都走 `encodeURIComponent('sys:' + key)`，產出的網址完全一樣（冒號會編成 `%3A`）。
`validate-tracker-pages.mjs` 之外另有一支 jsdom 回歸驗「site-index 的 key 全部對得上卡片」——
對不上的話命令面板會安靜地捲不到東西，畫面上完全看不出來。

## 4. 寫新頁面時的三條

1. **先讀網址再 `replaceState`**（§3.17）。順序顛倒的話 hash 會被自己洗掉——
   市場頁踩過，見 `market.js` 的 `pendingHash` 註解。
2. **只把「使用者會想分享的狀態」寫進網址**。展開／收合、hover、暫存輸入不要寫。
3. **回來補這張表。** 這份文件的價值在於「新人寫第 31 個工具時會先看一眼」，
   沒補的話下次又會冒出第三種分頁寫法。
