> 為 FFXIV 繁體中文伺服器玩家打造的工具集合，記錄各功能應有的功能細節。

# 一、日常工具

## 1.1 天書奇談計算器 ✅
**路徑**：`/tools/wondrous-tails/`

核心功能
- 輸入目前已揭開的格子位置（4×4 共 16 格，貼上 9 個任務獎勵章）
- 以 Monte Carlo 模擬計算完成 1 / 2 / 3 連線的機率
- 「重貼」（Second Chance）建議：比較保留現況 vs 使用重貼點重抽的期望連線數
- 輸出建議：應保留還是重貼、各連線數的機率分布

應有但可補強
- 重貼點剩餘次數輸入，連動建議
- 視覺化 4×4 棋盤點擊輸入（取代純文字座標）
- 顯示每週獎勵清單（成長之痂/詩學等）對照

---

## 1.2 仙人微彩計算機 ✅
**路徑**：`/tools/cactpot/`

核心功能
- 輸入已翻開的格子數字（3×3 盤面）
- 期望值計算：建議下一張該翻哪格、最後該選哪條線（8 條線）
- 對照賠率表換算 MGP 期望收益

應有但可補強
- 「最小仙人微彩」（Mini Cactpot）與「仙人微彩」（Jumbo，每週開獎）切換
- MGP 期望值換算成常見兌換品（如笛子、地圖坐騎）需要的場次估算

---

## 1.3 限時採集節點查詢 🛠️
**路徑**：`/tools/gathering/`（已有頁面）

核心功能
- 列出限時採集節點（傳說/稀有物品）：物品名、採集職業（採礦/園藝）、地圖、座標
- 出現時間（Eorzea Time 起訖）與下次出現倒數計時
- 以現實時間換算 ET（ET = 現實時間 × 20.5714）即時更新倒數

應有功能
- 篩選：依職業、依版本、依地圖、依物品類型（素材/收藏品）
- 即將出現排序（最近要刷的排前面）
- 點擊節點顯示 Teamcraft 座標與 flag 指令（可複製 `/coord`）
- 我的追蹤清單：勾選關注節點，只看關注的倒數
- 收藏品節點標記（需高採集數值）

資料來源：Teamcraft nodes JSON（追版本更新）

---

## 1.4 B 怪討伐路線 📋
**規劃路徑**：`/tools/hunt-b/`

範圍限定：僅 B 級怪（不做 A/S，因 A/S 需即時聯動社群回報，維護成本高）

核心功能
- 各資料片地圖的 B 怪固定刷新點位置與座標
- 每日討伐路線建議：依地圖串連最短路徑
- 顯示 B 怪掉落（狩獵物資/獎章）與所需數量
- flag 座標可複製

應有功能
- 依資料片 / 地圖篩選
- 勾選已討伐，路線自動跳過
- B 怪重生時間提示（擊殺後冷卻）

---

## 1.5 風脈泉追蹤器 📋
**規劃路徑**：`/tools/aether-currents/`

核心功能
- 各飛行地圖的風脈泉清單：地圖採集型（10 個）+ 任務型風脈泉
- 標示每個風脈泉座標、採集型 flag、任務型來源 NPC/任務名
- 進度追蹤：勾選已收集，顯示「還差幾個可飛行」

應有功能
- 依地圖分組，顯示各地圖 x/總數 進度
- 進度本機儲存（localStorage / 匯出匯入 JSON）
- 採集型風脈泉地圖預覽圖（座標標點）

資料來源：A Realm Remapped / Teamcraft 風脈泉座標可參考

---

## 1.6 時尚品鑑推薦 📋
**規劃路徑**：`/tools/fashion-report/`

核心功能
- 顯示本週時尚品鑑（Fashion Report）主題與評分項目
- 各部位推薦裝備 / 染色組合（達 80 分以上）
- MGP 獎勵說明（首次達標 / 滿分差異）

維護注意：每週更新，需半自動（社群解答抓取或手動填）。建議做成讀取一份每週更新的 JSON。

> 共通設計：所有收藏追蹤頁面採用同一套 UI 與資料結構，差異只在資料來源與分類。

## 收藏追蹤共通規格

每個收藏頁面都應具備：
- **總進度條**：已取得 / 總數，百分比
- **分類分頁**：依取得方式（任務/副本/商店/活動/成就/採集等）分組
- **每個項目卡片**：圖示、名稱（繁中）、取得方式說明、是否已取得勾選
- **篩選**：已取得 / 未取得 / 全部；關鍵字搜尋
- **進度保存**：localStorage 儲存，提供匯出 / 匯入 JSON（換裝置可帶走）
- **資料來源標註**：每個項目可連結灰機 Wiki / Teamcraft

維護注意：收藏品「取得方式」需手動對照 wiki，是最耗工部分，每大版本需補充。

## 3.1 配裝規劃器 ✅（外部連結）
- 外連 https://gearing.ffsusu.com/
- 維持外連即可，不自建（避免重複造輪子）

## 3.2 冒險者小隊計算機 ✅
**路徑**：`/tools/squadron/`

核心功能（皆已實作）
- 名冊固定 8 格（4 欄 × 2 列，對應遊戲上限）；隊員屬性由「目前職業」＋等級查 `memberGrowth` 成長表
- 隊員可轉職（〈戰鬥技巧教材〉三本的職業對照內建於參考面板）
- **每個任務自動從名冊挑出最佳 4 人並標出派遣名單**，不需手動勾選出擊
- 33 筆任務以表格呈現，屬性欄為「**出擊隊伍實際數值 / 任務門檻**」，未達標標紅並顯示「差 N」
- 任務列表分頁籤：全部／簡單／普通／特殊／重要任務（各標筆數，選擇會記住）
- 等級／成功率／軍票／經驗四欄可點擊排序（升→降→取消），排序狀態會記住
- 「名冊能力上限」面板：三項各自取任選 4 人的最高值，並列出各是哪 4 人

應有功能（皆已實作）
- 吉兆（Chemistry）23 種效果 × 26 種觸發條件模擬，條件成立與否真的影響數值；卡片上收合顯示
- 訓練池（依小隊階級 200/280/400 上限；超上限時由**沒被訓練到的屬性平均分攤扣抵，一律以 20 為單位**）
- 任務獎勵：軍票消耗、經驗值、獎勵道具繁中名
- 由遊戲內看到的門檻反推當週是第幾組配置
- 指令任務作戰方針（4 種）參考表

已知未做
- **指令任務（副本同行）本身沒有模擬**——只有作戰方針的數值參考表，沒有戰鬥推算
- 升等試算（練到 Lv60 要跑幾趟哪個任務）
- 任務等級門檻只警示不歸零（社群對規則說法不一致，見知識庫 §4.19）

## 4.1 市場查價工具 ✅
**路徑**：`/market/`

## 4.2 製作利潤計算機 📋（繁中空缺，優先）
**規劃路徑**：`/tools/crafting-profit/`

核心功能
- 選擇要製作的成品 → 自動展開材料樹（多層配方）
- 每個材料查 Universalis 市價，計算：
  - 全買材料製作成本
  - 成品售價（HQ/NQ）
  - 預估利潤 / 利潤率
- 標示哪些材料「買成品比買料便宜」（建議直接買半成品）

應有功能
- 數量設定（做幾個），總成本/總利潤
- 採集材料標記（可採集的不計入成本，或單獨估算）
- 伺服器 / DC 切換
- 排序：依利潤率找「現在做什麼賺」

參考：Frozen Rabbit's Workshop（備料 + 比價），定位為互補/整合而非重複

## 4.4 藏寶圖採集點查詢 📋

## 4.5 園藝配種計算 ✅
**路徑**：`/tools/gardening/`（2026-08-12 重做）

核心功能
- **配種路徑**：選目標作物 → 解出最省的**多層**配種路徑（不是只列一層配方），輸出階段化步驟、
  總工期、尖峰佔用格數，並依「開始種的時間」推算每階段的收成時刻
- **花色配方**：24 種花 × 9 色的油粕配方（含原色、隨機色標記）
- **全部作物**：搜尋／分類／排序，附圖示、種子取得管道、培育時數
- **機制速查**：配種判定時機與鄰接順序、土壤、照料、油粕染色（附出處連結）

**不做「正查」**（選兩株種子看配出什麼）——使用者不會這樣問問題，2026-08-12 移除。

關鍵事實（細節見 [gardening-rules.md](gardening-rules.md)）
- 配種**收到的是種子不是作物**，還要再種一輪才有目標作物 → 時數不是查表能得到的
- 「直接可得」不能認市場板，否則整棵樹縮成一層
- 成本模型要用**定點迭代**，配種關係有環

## 4.11 製作模擬器 ✅
**路徑**：`/tools/crafting-sim/`（2026-08-25 上線）

核心功能
- 選配方（搜尋成品繁中名／職業／最低等級）＋填工匠數值（等級、作業精度、加工精度、CP、專家）
- 工匠數值**八個職業各存一組**，選配方時自動調用該配方職業的那一組；另有「套用到所有職業」
- 版面依使用時機分頁：**① 準備**（選配方＋工匠數值）／**② 排循環**（左＝技能面板、右＝目前循環）／說明
- 排一串製作技能 → **循環清單的每一列就是那一步**，右邊直接顯示做到當下的作業／品質／耐久／CP（不另開逐步表）
- 技能面板**即時反映目前循環結尾的狀態**：等級／專家／CP／內靜／儉約衝突／一次限用都會標出原因，連段成立會標 ▶ 與折扣後 CP
- 滑過或鍵盤選到技能會顯示**官方說明文**＋「接在目前循環後」的即時試算
- 固定在畫面下緣的結果摘要條（判定＋四條進度條＋HQ），完整判定與隨機模擬在彈窗
- 技能可拖曳排序，並有等價的鍵盤操作（每一列上的 ←／✕／→）
- HQ 材料換算初期品質；收藏品顯示品質門檻；配方的數值門檻未達成會直接標示
- 成敗三態：作業滿＝完成、耐久歸零而作業沒滿＝失敗、兩者都沒發生＝**還在進行中**（不是失敗）
- 「跑 200 次」的隨機模擬：擲作業狀態與技能成功率，給完成率與 HQ 分佈
- 產生遊戲內巨集：超過 15 行（遊戲上限）自動切段，**每段各自一個框與複製鈕**，技能名為台服官方用字
- 四套內建範本、可分享網址、數值存本機

**規則出處與驗證**：見 [crafting-sim.md](crafting-sim.md)。公式移植自 Teamcraft 模擬器（MIT）並以其官方測試案例回歸；技能繁中名取自台服語系檔，CP 與等級對 XIVAPI 校驗。

> 與 4.2「製作利潤計算機」的分工：利潤／成本試算已在 4.1 市場查價頁實作（製作計畫、買 vs 做），本頁只管「這串手法做不做得出來、HQ 多少」。

# 五、跨功能共通建議

1. **進度保存統一**：所有「追蹤類」功能（收藏、風脈泉、釣魚、採集、幻卡等）共用一套 localStorage + 匯出/匯入 JSON 機制，最好能整合成一個帳號式的本機存檔。
2. **天氣演算法共用模組**：天氣預報、探索筆記、優雷卡、釣魚都要用到 ET/天氣計算，抽成共用 JS module（`assets/js/eorzea-time.js` 之類）。
3. **繁中名稱共用模組**：物品/技能繁中名稱統一走「簡中 datamining + OpenCC」的同一份資料與轉換邏輯，避免各頁面各自處理。
4. **flag 座標複製**：採集、藏寶圖、B 怪、風脈泉都需要「複製 `/coord` 指令」功能，抽成共用元件。
5. **版本標註**：資料來源於特定版本（採集點、配方）的頁面應標明對應遊戲版本，方便大版本更新時排查。

# 六、建議開發優先序

依「免維護程度 × 繁中空缺程度」排序：

| 優先 | 功能 | 理由 |
|------|------|------|
| 1 | 製作利潤計算機 | 繁中空缺、純計算（走 API）、需求高 |
| 2 | 限時採集節點查詢（補強） | 已有骨架、純演算法倒數 |
| 3 | 風脈泉追蹤器 | 純資料 + 進度追蹤，免持續維護 |
| 4 | 優雷卡天氣・NM | 天氣純演算法，可重用模組 |
| 5 | 物品/製作搜尋 | API 驅動，是製作利潤的基礎 |
| 6 | 探索筆記 / 釣魚 | 重用天氣模組 |
| 7 | 各收藏追蹤 | 量大且需手動維護來源資料，分批做 |
