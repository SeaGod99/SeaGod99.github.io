# 製作模擬器（tools/crafting-sim/）

排一串製作技能，逐步算出作業進度、品質、耐久、CP 與 HQ 機率，並產生遊戲內巨集。
2026-08-25 上線。本文記錄**規則從哪來、怎麼驗、哪裡刻意跟參考實作不一樣**——
公式的取整點很多，改錯了畫面完全看不出來，所以每一條都要有出處。

## 1b. 版面：依「使用時機」分頁

2026-08-25 改版。原本是「設定＋循環」左欄、「結果」右欄的兩欄式，問題是**選配方與工匠數值
跟製作過程無關**，卻一直佔著版面；而排技能時真正需要盯的是循環與當下數值。現在是：

| 分頁 | 內容 | 為什麼 |
|------|------|--------|
| ① 準備 | 選配方（含 HQ 材料）＋工匠數值 | 設定完就不用再看，做完按「去排循環」 |
| ② 排循環 | **左＝技能面板、右＝目前循環** | 排技能的雙手工作區，兩邊都要同時看得到 |
| 說明 | 規則與資料出處 | 少數人偶爾看 |

不分頁的兩塊：

- **情境列**（頁面最上方）：現在在模擬哪個配方、用哪一職的數值。換分頁也還在。
- **結果摘要條**（固定在畫面下緣，只在②出現）：判定圖示＋作業／品質／耐久／CP 四條迷你進度條
  ＋HQ 機率＋「完整結果」。彈窗裡只放**判定與隨機模擬**。

**逐步明細沒有獨立表格**——循環清單的每一列就是那一步，右邊直接顯示做到那一步當下的
作業／品質／耐久／CP。另開一張逐步表會逼使用者在兩個地方對照「第幾步」。

### 技能面板即時反映狀態

技能鈕會依**目前循環的結尾狀態**變化，資料來自引擎的 `previewNext()`：把
`rotation + 這一招` 整串重跑、取最後一步。**刻意不另外寫一套可用性判斷**——
連段折扣、內靜階數、耐久不足半效都是狀態相關的，兩套邏輯遲早各說各話。

- 等級／專家不符 → 🔒 標記（虛線框）
- 現在用不了 → ⚠ 加原因（CP 不足會寫「需 46，剩 10」、需要內靜、儉約期間不可用…）
- 連段成立 → ▶ 標記並顯示折扣後的 CP
- 已經有結果 → 不再逐顆標記，改成整張卡一句話（每顆都標只是噪音）

滑過或鍵盤選到會出現說明浮層：**官方說明文**（來自台服語系檔）＋
「接在目前循環後：連段成立、品質 +813、CP −18、耐久 −10」。

## 2. 規則從哪來

遊戲客戶端**沒有**把技能效率、增益倍率、作業狀態機率寫進可讀的 sheet。全世界的模擬器
都是社群逆向出來的常數，本站也不例外：

| 東西 | 來源 | 可驗證性 |
|------|------|---------|
| 技能繁中名 | Teamcraft `tw/tw-craft-actions.json`＋`tw/tw-actions.json` | 台服官方字串，**不可簡轉繁** |
| CP、解鎖等級 | XIVAPI v2 `CraftAction`／`Action` sheet | 建置時逐項比對，不符會印警告（目前 36/36 相符） |
| 效率、增益倍率、狀態機率、連段規則 | [Teamcraft 模擬器](https://github.com/ffxiv-teamcraft/simulator)（MIT） | 以該專案的官方測試案例回歸 |
| 配方的除數／修正／HQ 材料貢獻 | Teamcraft `recipes.json`（源自 `RecipeLevelTable`） | 逐筆與 rlvl 表交叉比對，不一致會印警告 |
| 工匠等級 → rlvl 對照、品質% → HQ% 對照 | Teamcraft `tables.ts`（社群共用常數） | 無官方出處，隨對照表走 |

### 名稱：查得到才寫，查不到不硬翻

作業狀態（球色）的台服官方字串是這樣挖出來的：

- **高品質／最高品質** — 出自技能說明（秘訣：「只有在『高品質』或以上的狀態下才能使用」）
- **結實／安定／高效／長持續／大進展** — 出自道具說明（素材奇跡列出六種狀態名）
- **一般／品質下降／下次高品質／耐久強固** — **台服字串查不到**。依專案鐵則不硬翻，
  改用效果描述當標籤，並在頁面說明裡講明白。找到官方字串再換掉。

其他順手確認到的官方用字：**內靜**（Inner Quiet）、**工匠的良機**（Expedience，倉促的追加效果）、
**高難度配方**（expert recipe）。

## 2b. 成敗有三種狀態，不是兩種

**製作的成敗只由「耐久歸零前作業有沒有滿」決定**，所以 `run()` 回傳的 `status` 有三個值：

| status | 條件 | 畫面 |
|--------|------|------|
| `done` | 作業滿了（收藏品另看品質門檻） | ✅ 製作完成 |
| `failed` | 耐久歸零而作業沒滿 | ❌ 製作失敗 |
| `ongoing` | 兩者都還沒發生 | 🔨 還在進行中：作業還差 N、耐久還剩 M |

**排到一半的循環是「進行中」，不是失敗。** 早期版本把它畫成 ❌「作業未完成」，
使用者會以為循環寫錯了——其實只是還沒排完。`success` 仍是布林（`done && 品質門檻過`），
判斷「還沒有結果」請看 `status`。

## 3. 刻意與 Teamcraft 不同的兩處

寫在 `craft-engine.js` 檔頭，這裡再記一次——**不要當成 bug 修掉**：

1. **隨機模式會真的擲作業狀態。** Teamcraft 的 `run()` 每一步都把狀態重設成「一般」，
   除非呼叫端逐步指定。那對「重播一場已發生的製作」是對的，對「預估這套循環會不會成功」
   則會讓高品質／最高品質永遠不出現。本引擎在 `linear=false` 時把 `tickState` 的結果
   帶到下一步，跟實際遊戲一致。
2. **不消耗作業時間的技能不推進作業狀態。** 最終確認、專心致志、快速改革的官方說明都寫
   「使用本技能不會消耗一次作業時間」，所以它們不該重擲球色（Teamcraft 只排除了最終確認）。
   設計變動照樣推進，因為它的效果就是「變更一次作業狀態」。

## 4. 驗證

```bash
node scripts/validate-craft-sim.mjs
```

- **公式**：移植 Teamcraft `test/simulation.spec.ts` 的期望值（取整、連段 CP、闊步／改革交互、
  高效／結實的減免、專心致志的消耗時機、工匠的絕技、冒進的前置條件…）。
- **範本**：頁面內建的四套範本，逐套在「宣稱的驗證條件」下實跑，必須完成且沒有任何一步被跳過。
  範本是唯一「我們自己宣稱可行」的東西，改了引擎沒重驗＝直接騙人。

目前 76 項全過。**改 `craft-engine.js`、`data/craft-actions.json` 或範本後必跑。**

## 5. 範本怎麼來的

不是憑印象抄巨集——**憑印象排的四套當初全都做不完**（在引擎裡實測，進度差 1500 以上）。
改用離線的兩階段 beam search 解出來，再把驗證過的結果寫死進 `crafting-sim.js` 的 `TEMPLATES`：

1. **階段一（作業）**：只用作業與增益／修復技能推進度，停在「還差一招就能完成」的狀態，
   評分偏好剩餘 CP 與耐久。
2. **階段二（品質）**：從階段一的狀態接著堆品質，最後補上收尾那一招。

兩個關鍵發現，之後要重解時直接沿用：

- **必須兩階段**：單純的 beam search 會被「作業進度」帶著走，因為品質技能的報酬是延遲的
  （要先疊內靜），貪心的評分永遠選不到它們。第一版解出來只有 4297/12000。
- **評分要把增益的價值算進去**（改革／闊步／掌握／儉約的剩餘步數各給權重），
  否則 beam 永遠不會去點改革——花 18 CP、當下品質零成長，分數一定比不點差。
  加上這條之後同一個配方從 5422 → 7230。

求解腳本是一次性的，沒有進 repo（跑在暫存區）。要重解時照上面兩點重寫即可，
或直接把它做成頁面上的「自動求解器」——目前刻意**沒做**，v1 只做手動排＋範本。

## 6. 已知範圍外

- **宇宙探索（7.2）的專用技能**（恆星堅穩之手、素材奇跡）沒收。它們只在星際任務裡能用，
  而且那些配方不在 `recipes.json` 裡。
- **高難度配方**（expert，480 筆）可以模擬，狀態機率也照 `conditionsFlag` 走；
  但「下次高品質／耐久強固」兩種狀態沒有官方繁中名（見 §2）。
- **收藏品**只看 `requiredQuality` 這道門檻，不算收藏品等級的分級。
- **工匠數值八職各存一組**（`ffxiv_craftsim_stats`，格式 `{v:2, lastJob, jobs:{jobId:數值}}`）。
  選配方時自動切到該配方職業的那一組。**舊的單一組平面格式會自動遷移**（複製到八職），不要拿掉那段。

## 7. 台服升版後要做什麼

1. `node scripts/build-craft-sim.mjs`（不帶參數＝重抓 Teamcraft 與 XIVAPI）
2. 看有沒有印出「CP 不符／等級不符／查無台服官方名」——有就是官方調整了技能，要跟著改
   `ACTIONS` 表裡的效率或旗標
3. `node scripts/validate-craft-sim.mjs`
4. `node scripts/validate-data.mjs`

新配方會自動跟著 `data/recipes.json` 進來（記得那份要先更新），版本閘門是前端做的，
`_meta.json` 的 gamePatch 一改就生效。
